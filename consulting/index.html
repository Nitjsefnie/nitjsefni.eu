Harness build

2 to 3 weeks 4,800 EUR, fixed

  • Repository instruction files stating the rules your agents follow, written to be loaded at the start of every session rather than pasted into a prompt.
  • A skill catalogue for the procedures your team repeats, so an agent runs your procedure instead of inventing one each time.
  • Hooks that deny the tool calls which break a rule, where the denial names the correct next step instead of just failing.
  • Commit, pull request and issue conventions, with the templates and local checks that hold agent work to them.
  • An attribution trail: every commit an agent produced carries a co-author trailer, verified before the push rather than after.

CI hardening and release provenance

1 to 2 weeks 2,400 EUR, fixed

  • A test workflow across the operating systems and language versions you actually support, with coverage measured once rather than once per matrix cell.
  • Lint, type checking and static security analysis as separate checks, so a red build names its own cause.
  • A dependency audit on a daily schedule, because a version you froze months ago stops being safe with no commit of yours to hang the failure on.
  • Workflow linting with actionlint and zizmor: a broken workflow does not go red, it silently stops running.
  • Releases that publish checksums and build attestations beside the artifact, so a download can be traced back to the commit and the runner that built it.

How it works

The work is asynchronous: scoping, quote, delivery and handover all happen in writing.

  1. Scoping

    You send a short brief by email: the repository, the team, the agents you run, and what is going wrong. I ask what I need to quote it, by email, usually within one working day.

  2. Fixed quote

    A written scope narrowing the deliverables above to your situation, with one price, a start date and an end date. Nothing begins until you accept it in writing.

  3. Delivery

    Work arrives as commits on a branch in your repository, one logical change each, with a running note of what changed and why. You can stop at any point and keep everything that has landed.

  4. Handover

    A written runbook for extending the setup yourselves, plus a written question round afterwards. Everything is plain files in your repository, with nothing of mine left to pay for.

Who this is for

If the right-hand list describes you, say so in the first email and we both save the time.

Worth writing to me

  • Your team already runs Claude Code or Codex daily, and someone is policing the output by hand.
  • You have CI, and you want agent work to pass the same gates as human work.
  • You cannot currently say what a month of agent usage cost, per model or per repository.
  • You want the setup to be yours afterwards, in files you can read and change.

Not a fit

  • You want agents running without gates or review. The method here is refusing the work that breaks a rule.
  • There is no repository to work in, or configuration and transcripts cannot be shared under an agreement.
  • You are looking to buy model access or agent subscriptions. I configure what you already pay for.
  • You want a finished application built for you. This is tooling around your engineers, not a replacement for them.
